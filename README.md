# Lesta Shop

SPA-витрина игровой техники, реализованная на React, TypeScript, React Router и CSS Modules.

Проект показывает каталог техники в двух разделах: `Премиальная` и `Коллекционная`. Раздел выбирается через роутинг, фильтры и сортировка сохраняются в URL, карточки можно фильтровать по типу техники и сортировать по актуальной цене с учетом скидки.

## Стек

- React 19
- TypeScript
- React Router
- CSS Modules
- Vite

## Функциональность

- Два раздела каталога: `premium` и `collection`.
- Переключение разделов через роутинг.
- Валидация типа каталога из URL.
- Фильтрация по нескольким типам техники одновременно.
- Сортировка карточек по актуальной цене.
- Сохранение фильтров и сортировки в URL.
- Loader при переключении разделов каталога.
- Адаптивная верстка для desktop и mobile.
- Staggered-анимация появления карточек.

## URL-параметры

Фильтрация использует множественные значения `types`:

```txt
/premium?types=lightTank&types=mediumTank
```

Сортировка сохраняется в параметре `sort`:

```txt
/collection?types=SPG&sort=desc
```

Если `types` не передан, показываются все машины текущего раздела.

## Актуальная цена

Сортировка выполняется по актуальной цене:

- если у машины есть скидка, используется `price`;
- если скидки нет, используется `old_price`.

## Архитектура

Проект организован в feature-oriented стиле, близком к FSD:

- `app` - инициализация приложения, роутинг и layout.
- `pages` - страницы маршрутов и их композиция.
- `widgets` - крупные блоки интерфейса, например навигация каталога.
- `features` - пользовательские сценарии: сортировка по цене и фильтрация по типу техники.
- `entities` - доменная модель техники, API-абстракция, helper-функции и UI карточек.
- `shared` - переиспользуемые UI-компоненты и низкоуровневые утилиты.
- `styles` - глобальные стили, CSS-токены и подключение шрифтов.
- `data` - статические JSON-данные.

Данные о технике скрыты за API-слоем в `entities/vehicle/api`. Сейчас API читает локальный JSON и имитирует задержку загрузки, но страницу можно перевести на реальный `fetch` без изменения UI-компонентов.

Статические данные лежат в `src/data`. Бизнес-логика фильтрации, сортировки и вычисления актуальной цены вынесена в `entities/vehicle`, чтобы не смешивать данные, доменную логику и UI.

## Запуск проекта

Установить зависимости:

```bash
npm install
```

Запустить dev server:

```bash
npm run dev
```

Собрать production build:

```bash
npm run build
```

Проверить код линтером:

```bash
npm run lint
```

Посмотреть production build локально:

```bash
npm run preview
```

## Ограничение по данным

В Figma-макете есть большая карточка набора, но в исходных данных отсутствует отдельная структура для наборов: нет сущности набора, состава набора и связи нескольких машин с одной большой карточкой.

Из-за этого большая карточка из макета не создавалась как отдельный тип карточки. Текущая реализация строит список из доступных данных о технике и отображает обычные карточки машин. Для полноценной большой карточки нужен отдельный слой данных, например `bundle`, `bundle_items` или аналогичная структура, которая описывает набор и его содержимое.

Также текущий API является mock-реализацией поверх локального JSON. Это сделано для тестового задания; слой API отделен от UI, поэтому источник данных можно заменить без переписывания страницы каталога.
